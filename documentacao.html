1. Resumo Executivo & Filosofia de Design

Ecos do Andarilho não é apenas um platformer 2D; é um exercício académico rigoroso focado na sincronização de subsistemas díspares — renderização visual, simulação física de corpos rígidos e processamento de sinal digital em tempo real — sob o ambiente altamente restritivo e single-threaded (maioritariamente) do JavaScript no navegador.

i

Visão Principal (Core Pillar)

O áudio não dita apenas a atmosfera; dita as regras do motor. O mundo (gravidade, fricção, raycasting de inimigos) reage programaticamente à amplitude das frequências baixas da faixa musical em reprodução.

Os 3 Pilares do Game Design (GDD)

  • Precisão Determinística: O jogador nunca deve falhar por latência do motor. O input deve ser lido independentemente do gargalo de renderização visual.
  • Legibilidade Visual: Num jogo de ritmo acelerado, a arte Pixel Art não é apenas uma escolha estética, mas funcional. Elementos letais contrastam ativamente na roda de cores contra o cenário.
  • Fricção Nula de Onboarding: Utilizar HTML5 significa *Zero-Install*. O jogo tem de compilar os recursos iniciais para a RAM em menos de 3.5 segundos em redes 4G.

2. Stack Tecnológica & Dependências

A arquitetura foi dividida entre o invólucro do portal (Landing Page) e o binário do motor do jogo para garantir paralelismo no desenvolvimento entre os membros da equipa.

Construct 3 (Core)

Motor de jogo exportando o novo C3Runtime puro em ES6. Otimizado para não depender do antigo padrão asm.js, garantindo execução nativa V8 e compilação de scripts customizados sem transpiling forçado.

Frontend DOM

HTML5 Semântico e CSS3 com variáveis nativas (Custom Properties). Sem frameworks pesados (React/Angular) para não competir pelo Main Thread com o Canvas do jogo. Interações de DOM animadas via GSAP 3.12.

Hardware APIs

Comunicação direta com WebGL 2.0 (para shaders e batching de texturas), WebAudio API (para manipulação e buffering de som estéreo 44.1kHz), e Gamepad API (suporte nativo a comandos Xbox/PlayStation).

4. Arquitetura do Game Loop

Problema clássico no desenvolvimento Web: O requestAnimationFrame liga-se à taxa de atualização do monitor do cliente (60Hz, 120Hz, 144Hz, 240Hz). Se a simulação da física correr no mesmo ritmo do monitor, um jogador a 144Hz sofrerá a força da gravidade com o dobro da rapidez de um jogador a 60Hz.

!

A Solução: Fixed Time Step com Interpolação

Implementou-se um "acumulador". O tempo delta real transcorrido (variável) é acumulado. A simulação física apenas consome o tempo em parcelas fixas rigorosas (ex: 1/60 seg). O que sobra no acumulador é utilizado na fase de renderização (WebGL) para interpolar a posição visual dos *sprites*, resultando em movimento suave independente do ecrã.

core/GameLoop.js
class GameEngine { constructor() { this.FIXED_TIME_STEP = 1.0 / 60.0; // Garante determinismo a 60 Updates/seg this.MAX_FRAME_TIME = 0.25; // Evita a 'Espiral da Morte' (Freeze tab) this.accumulator = 0.0; this.lastTime = performance.now(); } start() { requestAnimationFrame((time) => this.tick(time)); } tick(currentTime) { let frameTime = (currentTime - this.lastTime) / 1000.0; this.lastTime = currentTime; // Prevenção contra pausas longas (mudança de tab do browser) if (frameTime > this.MAX_FRAME_TIME) { frameTime = this.MAX_FRAME_TIME; } this.accumulator += frameTime; // Consome o tempo em parcelas exatas while (this.accumulator >= this.FIXED_TIME_STEP) { this.updatePhysics(this.FIXED_TIME_STEP); this.updateGameLogic(); // Atualiza AIs e Máquinas de Estados this.accumulator -= this.FIXED_TIME_STEP; } // Calcula o resto para suavização visual (Lerp) const alpha = this.accumulator / this.FIXED_TIME_STEP; this.renderWebGL(alpha); requestAnimationFrame((time) => this.tick(time)); } }

5. Pipeline WebGL 2.0 & Renderização

Num jogo com centenas de tiles de cenário, desenhar textura a textura na API do Canvas 2D tradicional reduziria as taxas de fotogramas para a casa dos 15fps num telemóvel.

Estratégia de RenderizaçãoImplementação no Motor
Sprite Atlasing Em tempo de compilação, centenas de ficheiros PNG dispersos são agregados numa mega-textura única de 2048x2048. Ao desenhar o mapa, o WebGL só precisa de vincular a textura à GPU uma vez (evitando o custoso glBindTexture), mudando apenas as coordenadas UV (Texture Mapping) para renderizar a relva, o céu e os inimigos simultaneamente.
Batching & Instancing Recurso a gl.drawElementsInstanced. Se existem 500 blocos de pedra idênticos no nível, enviamos à placa gráfica a malha do bloco 1 única vez, junto com um vetor (Buffer) contendo as 500 posições de mundo (Matrizes de Translação). O Draw Call Overhead é aniquilado.
Nearest-Neighbor Filtering Para manter a nitidez gloriosa do Pixel Art quando esticado em ecrãs 4K, o filtro WebGL passa de gl.LINEAR para gl.NEAREST. A engine garante que o ecrã desenha os píxeis bloqueados em grelhas exatas, impossibilitando texturas turvas e o indesejado "anti-aliasing" natural dos browsers.

6. Motor de Áudio DSP (FFT)

A alma do jogo. A Web Audio API fornece muito mais do que apenas a tag <audio>. Foi instanciado um AudioContext que canaliza o fluxo sonoro através de um AnalyserNode capaz de efetuar a Transformada Rápida de Fourier (Fast Fourier Transform - FFT) em tempo real, decompondo as ondas sonoras no domínio da frequência.

audio/SpectrumAnalyzer.js
export class SpectrumAnalyzer { constructor(audioElement) { this.ctx = new (window.AudioContext || window.webkitAudioContext)(); this.source = this.ctx.createMediaElementSource(audioElement); this.analyser = this.ctx.createAnalyser(); // Resolução da FFT. 256 é ideal para jogos rítmicos (alta reatividade, menos detalhe) this.analyser.fftSize = 256; this.analyser.smoothingTimeConstant = 0.2; // Decaimento rápido para não colar o beat this.source.connect(this.analyser); this.analyser.connect(this.ctx.destination); this.bufferLength = this.analyser.frequencyBinCount; // 128 bins this.dataArray = new Uint8Array(this.bufferLength); this.BEAT_THRESHOLD = 210; // Amplitude necessária (0-255) para disparar o Eco } detectKickDrum() { this.analyser.getByteFrequencyData(this.dataArray); // Isola frequências graves extremas (ex: Bumbo da bateria / Bass) // Na taxa de 44100Hz, os primeiros 4 bins representam ~0Hz a 170Hz let bassEnergy = 0; for (let i = 0; i < 4; i++) { bassEnergy += this.dataArray[i]; } bassEnergy = bassEnergy / 4.0; // Retorna verdadeiro se ocorreu uma explosão de sub-graves return (bassEnergy > this.BEAT_THRESHOLD); } }

7. Sistema de Física Box2D & AABB

Toda a física do jogo é calculada utilizando Axis-Aligned Bounding Boxes (AABB). Estas caixas matemáticas invisíveis não podem ser rodadas (mantendo as arestas paralelas aos eixos X/Y do ecrã), garantindo que os cálculos de interseção no Processador ocorrem numa fração de milissegundo usando aritmética booleana básica em vez de cálculos trigonométricos de matrizes de rotação.

i

CCD (Continuous Collision Detection) vs Tunneling

Quando a gravidade se aproxima dos 2500px/s nas fases finais do jogo, o Herói adquire tanta velocidade entre fotogramas (DeltaTime) que numa frame estaria acima do chão, e na frame seguinte já estaria debaixo de terra, "atravessando" a colisão (Efeito Tunneling). A engine corrige isto realizando Raycasting Sweeps a cada atualização física, detetando o ponto exato temporal em que a intersecção iria ocorrer e encostando o personagem no solo precisamente nesse *pixel*.

8. Particionamento Espacial (QuadTree)

As florestas do jogo contêm mais de 4.000 polígonos de colisão. Testar a AABB do herói contra 4.000 caixas todos os fotogramas é impraticável. Implementámos a estrutura de dados QuadTree. O mundo é recursivamente subdividido em 4 quadrantes. O algoritmo só executa o teste de colisão custoso na meia dúzia de blocos de terra que habitam a exata mesma sub-região folha que o jogador ocupa no momento.

physics/QuadTree.js (Algoritmo Core)
class QuadTree { constructor(level, bounds) { this.maxObjects = 10; // Ponto de divisão do nó this.maxLevels = 5; // Profundidade máxima da árvore this.level = level; // Profundidade atual this.bounds = bounds; // Estrutura {x, y, width, height} this.objects = []; // Entidades físicas presentes neste nó this.nodes = []; // Os 4 sub-quadrantes filho } split() { const subWidth = this.bounds.width / 2; const subHeight = this.bounds.height / 2; const x = this.bounds.x; const y = this.bounds.y; // Quadrante Superior Direito (I) this.nodes[0] = new QuadTree(this.level + 1, { x: x + subWidth, y: y, width: subWidth, height: subHeight }); // Quadrante Superior Esquerdo (II) this.nodes[1] = new QuadTree(this.level + 1, { x: x, y: y, width: subWidth, height: subHeight }); // Quadrante Inferior Esquerdo (III) this.nodes[2] = new QuadTree(this.level + 1, { x: x, y: y + subHeight, width: subWidth, height: subHeight }); // Quadrante Inferior Direito (IV) this.nodes[3] = new QuadTree(this.level + 1, { x: x + subWidth, y: y + subHeight, width: subWidth, height: subHeight }); } retrieve(returnObjects, entityRect) { const index = this.getIndex(entityRect); if (index !== -1 && this.nodes.length > 0) { this.nodes[index].retrieve(returnObjects, entityRect); } // Adiciona apenas os blocos que partilham vizinhança real com o Jogador returnObjects.push(...this.objects); return returnObjects; } }

9. Game Feel: Input Buffering & Coyote Time

Um jogo de ritmo rigoroso pareceria profundamente quebrado (e injusto) nas mãos de humanos sem sistemas de auxílio ocultos. A programação destes sistemas de Game Feel invisíveis define a qualidade cinestésica da navegação.

Coyote Time

Se o jogador caminhar para fora de uma plataforma, não morre instantaneamente por falhar o salto no último píxel. A engine mantém a flag isOnGround = true durante exatos 120ms após o herói começar a cair no abismo, permitindo um salto aéreo compensatório apelidado de Wile E. Coyote.

Jump Buffering

O jogador envia comandos visuais/táteis com antecipação. Se o botão "Saltar" for pressionado 100ms antes de bater no chão ou de o "Eco" da música ecoar, o motor grava esse Input numa fila FIFO temporária. Quando a colisão no solo ocorre a seguir, o salto é executado imediatamente no fotograma 0 de contato perfeito.

mechanics/InputController.js
const JUMP_BUFFER_DURATION = 0.1; // Segundos de memória (100ms) const COYOTE_DURATION = 0.12; // Segundos flutuando no ar (120ms) let timeSinceJumpPressed = 999.0; let timeSinceLeftGround = 999.0; function evaluateMovement(dt) { // 1. Atualizar contadores de tempo (Ageing) timeSinceJumpPressed += dt; timeSinceLeftGround = (Player.onGround) ? 0.0 : timeSinceLeftGround + dt; // 2. Intercetar botões físicos (Teclado/Gamepad/Touch) if (InputSystem.isActionJustPressed('JUMP')) { timeSinceJumpPressed = 0.0; } // 3. Lógica Cruzada Magistral (The Game Feel Magic) const canCoyoteJump = (timeSinceLeftGround <= COYOTE_DURATION); const hasBufferedJump = (timeSinceJumpPressed <= JUMP_BUFFER_DURATION); if (hasBufferedJump && canCoyoteJump) { // Sucesso! O jogador saltou a tempo. Executar físicas de impulso. Player.velocityY = -Player.JUMP_FORCE; // Anula os buffers instantaneamente para impedir o efeito indesejado "Pogo Stick" timeSinceJumpPressed = 999.0; timeSinceLeftGround = 999.0; AudioEngine.playSFX('jump_whoosh'); } }

10. Máquina de Estados Finitos (FSM)

Gerir a animação, caixas de colisão de ataque e imunidade utilizando variáveis lógicas soltas (isJumping, isAttacking, isHurt) criaria um código conhecido como *Spaghetti*, sujeito a bugs gravíssimos como "atacar durante a morte". Para organizar a entidade principal, adotámos rigorosamente uma FSM (Máquina de Estados Finitos).

✓

A Regra de Ouro da FSM

O Player só pode habitar um estado singular a cada fotograma. A transição de um estado para o outro deve obedecer a uma Matriz de Transição de Transição validada. Por exemplo, só se transita de FALLING para IDLE se o vetor Raycast detetar contacto com a propriedade isSolid do solo.

entities/HeroStateNode.js
// Enumeração dos Estados Absolutos permitidos na arquitetura const STATES = Object.freeze({ IDLE: 0, RUNNING: 1, JUMPING: 2, FALLING: 3, DASHING_RHYTHM: 4, STUNNED: 5, DEAD: 6 }); class PlayerStateMachine { constructor() { this.currentState = STATES.IDLE; } switchState(newState) { if (this.currentState === STATES.DEAD) return; // Não há fuga da morte matemática. this.currentState = newState; // Atualiza logicamente a visualização (Sprite Atlas Rects) switch (this.currentState) { case STATES.IDLE: SpriteRenderer.playAnimation('hero_breathe'); break; case STATES.DASHING_RHYTHM: SpriteRenderer.playAnimation('hero_echo_burst'); Physics.gravityScale = 0.0; // Desliga gravidade no meio do Dash Especial break; case STATES.STUNNED: SpriteRenderer.playAnimation('hero_hurt_flashing'); Camera.screenShake(12, 0.4); // Impacto sensorial na UI break; } } }

11. Inteligência Artificial (A* & Ritmo)

Num Platformer, grande parte dos inimigos segue caminhos estáticos ou patrolhas em *loop*. Em "Ecos do Andarilho", uma variante singular de ameaças - os Stalkers Sónicos - utiliza uma grelha lógica para efetuar Pathfinding via algoritmo A* (A-Star) até ao jogador. No entanto, o seu movimento nunca é linear; é balizado pelo compasso da banda sonora.

Variável de IADescrição do Comportamento Paramétrico
Aggro Radius Raio esférico em píxeis calculando a hipotenusa (Teorema de Pitágoras) entre Entidade e Jogador. Caso a distância desça do limite imposto, o State alterna de PATROL para HUNT.
Rhythm Synchronization A velocidade transacional vetorial \(\vec{v}\) da Inteligência Artificial é multiplicada a 0, exceto quando o AudioAnalyser capta picos de bumbo. Isto faz os inimigos teleportarem em saltos microscópicos (Jumpscares ritmados) no lugar de andarem fluidamente.
Line of Sight (LoS) Um *Raycast* é emitido do olho do NPC à hitbox do herói. Caso o raio embata num Tile de propriedade Solid = true no caminho, o cálculo da IA entra em suspensão até que o herói reapareça no ângulo desobstruído.

12. Object Pooling & Gestão de V8 GC

Gerir a RAM é o segredo entre um jogo navegador correr a estáveis 60FPS num Smartphone Android obsoleto ou deitar a aplicação abaixo num Out Of Memory (OOM) Crash. Operadores new ou comandos de destruição desencadeiam o processo agnóstico de Garbage Collection (GC) da Engine V8. Quando este corre, a renderização pausa completamente.

!

A Otimização via Instanciação Persistente (Object Pool)

Se o jogador disparar 50 feitiços sonoros, a RAM não instancia 50 objetos na cena. Antes do nível sequer desvanecer do escuro (Load Screen), instanciamos de imediato 100 balas mortas (isActive = false) algures no vácuo de renderização (x=-9999, y=-9999). Premir o botão de tiro repesca uma das balas no vetor Pool e move-a para o ecrã. O GC não lida com reciclagens, logo, a latência de micro-solavancos é nula.

13. Serialização de Dados (IndexedDB Save System)

Para assegurar a continuidade da progressão (Checkpoints, Níveis Desbloqueados, Melhorias), implementámos persistência local no browser. A API básica localStorage tem o nefasto problema de ser Síncrona; guardar o jogo no ecrã faria o motor congelar por um segundo. Migrámos a arquitetura para a mais robusta, mas muito mais complexa, API assíncrona IndexedDB operada via transações e Promises.

systems/SaveManager.js (Assíncrono)
async function saveGameProgress(playerDataObj) { // 1. Transforma o grande objeto JS num texto codificado rigoroso const jsonPayload = JSON.stringify(playerDataObj); // 2. Comprime via Base64/LZString para ofuscação (Evita hacking de saves) e poupança const encodedBlob = LZString.compressToBase64(jsonPayload); // 3. Inicia transação Assíncrona no IndexedDB return new Promise((resolve, reject) => { const request = window.indexedDB.open("EcosDB", 1); request.onsuccess = (event) => { const db = event.target.result; const transaction = db.transaction(["save_slots"], "readwrite"); const objectStore = transaction.objectStore("save_slots"); const storeRequest = objectStore.put({ id: "slot_1", data: encodedBlob, timestamp: Date.now() }); storeRequest.onsuccess = () => resolve("Save successful!"); storeRequest.onerror = (e) => reject(e); }; }); }

14. Estrutura de Níveis (JSON Schema Level Design)

Desenhar os mapas da floresta no editor interno é fácil visualmente, mas como o jogo gera plataformas em execução via eventos de ritmo musical, um grande volume de Level Data tem de ser dinâmico e flexível. Usamos a serialização via matrizes multiobjetos JSON para armazenar informações espaciais de Spawn Points, grelhas e metadados de colisão por mundo.

levels/world_01_json.schema

Nota Arquitetural: O ficheiro JSON é lido sequencialmente na inicialização do Layout. Os números na `grid_matrix` correspondem a identificadores mapeados no interior dos Sprite Atlases (ex: 1 = Terra, 2 = Caixa Destrutível). Este parse reduz o peso do ficheiro em 95% contra matrizes baseadas noutras texturas brutas.

15. Infraestrutura de CI/CD (Vercel & Cache)

O ciclo de vida do software segue as diretrizes metodológicas do DevOps. O repositório está integrado nativamente na CDN global da Vercel para entregas contínuas (Continuous Deployment). Os binários gerados pela engine e as faixas MP3 (alguns chegam a pesar 15 MB) precisam ser fortemente cacheados nas Edge Networks, sem prejudicar atualizações críticas do HTML portal.

vercel.json (Edge Headers Protocol)
