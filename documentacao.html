1. Visão Geral do Sistema

Ecos do Andarilho é um jogo de plataformas 2D com mecânicas subjacentes de ritmo. A premissa de Engenharia de Software foca-se na sincronização perfeita entre a física rígida (Rigidbody Box2D adaptada) e buffers analíticos de áudio (BPM).

Conceito Central: O "Tick" Rítmico
A rotina de atualização (Update Loop) não avalia apenas colisões por frame (60fps), mas faz amostragem contínua do tempo de reprodução do AudioContext. As variáveis de gravidade e atrito mudam dinamicamente mediante a janela de tolerância de cada batida musical.

2. Arquitetura da Engine (Construct 3)

A compilação do jogo utiliza a exportação nativa HTML5 do Construct 3, rodando num contexto WebGL para aceleração de hardware em matrizes de sprites pesadas.

Renderer Pipeline (WebGL)

Utilização de Sprite Atlases gerados automaticamente no *build*. As camadas de parallax do cenário são renderizadas fora do pipeline de colisão, poupando processamento de CPU.

Web Audio API

Os ficheiros MP3 são descodificados antecipadamente na RAM (Pre-load Audio Buffer) evitando latência de disco, crucial para o cálculo rigoroso das tolerâncias rítmicas.

3. Espectro de Áudio e FSM

A programação avançada do sistema de "Ecos" substitui os controlos padrão. Para além da batida matemática, o jogo utiliza uma aproximação de Análise Rápida de Fourier (FFT) para identificar os kicks do baixo.

audio_analyzer.js (Pseudocode)
// 1. Parâmetros Globais do Motor Musical const trackBPM = 120.0; const secPerBeat = 60.0 / trackBPM; const toleranceWindow = 0.12; // 120ms para validar Input // 2. Máquina de Estados Finitos (FSM) do Herói const PLAYER_STATE = { IDLE: 0, RUN: 1, FALL: 2, ECHO_DASH: 3 }; let currentState = PLAYER_STATE.IDLE; // 3. Função Validatória Chamada a cada Input function evaluateRhythmAction(audioTime, inputType) { let moduloBeat = audioTime % secPerBeat; let isPerfectHit = (moduloBeat < toleranceWindow) || (moduloBeat > (secPerBeat - toleranceWindow)); if (inputType === 'JUMP' && isPerfectHit) { currentState = PLAYER_STATE.ECHO_DASH; return true; } return false; }

4. Pooling & Gestão de Memória

Sendo um ambiente HTML5 restrito (navegador), instanciar e destruir partículas no *Garbage Collector* causa quebras na taxa de quadros (stuttering).

Implementação de Object Pooling
Em vez de usar a ação Destroy() no motor para os efeitos de "Eco Ring", instanciamos 30 sprites em memória no início do *Layout* (fora do ecrã). Quando o jogador acerta o ritmo, o código apenas recicla uma partícula nativa livre movendo as suas coordenadas X/Y e disparando a animação novamente.
